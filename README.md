# Unity Core Sample

2023년부터 프로젝트마다 고쳐 쓰며 이어 온 Unity 공용 코어 중, **구조가 드러나는 한 줄기**만 뽑아 정리한 코드입니다.
부팅 순서 · 일시정지 · 팝업 닫는 순서에서 프로젝트마다 반복되던 문제를 구조로 막는 것이 목적입니다.

`Unity 6 (6000.0)` · `C#` · `uGUI`

---

## 읽는 순서

| # | 파일 | 무엇 |
|---|---|---|
| 1 | [`Core/AppInstance.cs`](Core/AppInstance.cs) | 부팅 — 무엇을 어떤 순서로 켜는가 |
| 2 | [`Core/Controllers/ControllerBase.cs`](Core/Controllers/ControllerBase.cs) | 동작 모듈 — 상위가 하위의 수명을 쥔다 |
| 3 | [`Core/Controllers/SubControllerBase.cs`](Core/Controllers/SubControllerBase.cs) | 하위 모듈 — 적용 · 일시정지 · 해제 |

## 구조

```
AppInstance ─── 부팅 순서를 코드가 아니라 배열이 정한다
   │
   ├── EventHub ──────── 서로 참조하면 안 되는 모듈 사이의 신호만
   │
   ├── PopupStack ────── 열기 · 보이기 · 닫기 창구 하나. 층(Layer)만 다르다
   │      └ PopupBase ── 보이기 · 숨기기 연출이 끝나면 콜백으로 알린다
   │
   ├── ControllerBase ── 동작 모듈의 최상위
   │      └ SubControllerBase ── 상위가 멈추면 같이 멈춘다
   │             └ VirtualJoystickController
   │
   └── WebGLBridge ───── 호스트 페이지(JS)와의 유일한 접점
```

## 왜 이 구조인가

| 결정 | 이유 |
|---|---|
| **상위가 하위의 수명을 쥔다** | 하위 모듈이 스스로 `Start()` 에서 시작하면 상위가 멈춰도 하위는 계속 돌았다. 일시정지 · 씬 전환에서 매번 터졌다. 그래서 `Initialize` · `SetRunning` · `Release` 를 상위가 부른다 |
| **부팅 순서를 배열로 뺐다** | 매니저가 늘 때마다 `Awake` · `Start` 에 한 줄씩 늘어나는 구조였고, 순서가 곧 버그였다. 지금은 `_bootSequence` 배열 순서가 부팅 순서다 |
| **팝업은 스택 하나로만** | 팝업마다 부모와 딤 패널을 직접 만지던 시절, 닫는 순서가 꼬이면 화면이 잠겼다. 생성 · 부모 지정 · 딤 처리를 `PopupStack` 한 곳으로 모았다 |
| **열기(Open)와 보이기(Show)를 나눴다** | 생성 직후에는 숨겨 둔다. 값을 채우는 동안 보이지 않고, 준비가 끝난 뒤에만 `Show` 로 연출을 시작한다 |

```
PopupStack.Open<T>()   생성 · 스택에 쌓기 (아직 안 보임)
   → 값 채우기
PopupStack.Show<T>()   보이기 연출 시작
PopupStack.Close<T>()  숨기기 연출 → 끝나면 파괴 · 딤 갱신
```

## 포기한 것

| 선택 | 대가와 대응 |
|---|---|
| 초기화 인자가 `object[]` | 타입 안전을 포기하고 유연함을 샀다. 프로젝트마다 받는 값이 달라 공용 코어가 타입을 고정하면 매번 베이스를 고쳐야 했다. 꺼내는 곳은 `TryTakeArgument<T>` 한 군데로 묶었다 |
| 싱글톤을 남겼다 | 주입(DI)이 더 깨끗하지만 씬을 직접 여는 테스트 흐름이 깨진다. 싱글톤은 `AppInstance` 하나로 줄였다 |

## 원본에서 바꾼 것

원본 **7개 파일 2,646줄 → 18개 파일 1,313줄**. 외부 에셋(Odin Inspector · DOTween)과 사내 유틸 의존을 걷어내고 표준 Unity API 로만 다시 썼습니다.

**정리하면서 찾은 원본 결함 (일부)**

| 원본 | 문제 | 조치 |
|---|---|---|
| `BreakPoint(true)` | 이름은 정지인데 실제 동작은 재개 | `SetRunning(bool)` |
| `Reset()` | Unity 에디터 콜백 예약어와 충돌 | `ResetLever()` |
| 필수 팝업 재정렬 | 2중 while 이 아무 일도 하지 않음 | 삭제 (동작 동일) |
| 소스 인코딩 | CP949 와 이중 인코딩이 섞여 주석 일부가 영구 손상 | UTF-8 로 저장, 깨진 주석은 다시 씀 |

## 검증

Unity **6000.0.24f1** 에 데모 씬을 만들고 **PlayMode 테스트 5개**로 실제 동작을 확인했습니다. (검증용 프로젝트는 이 저장소에 넣지 않았습니다)

| 테스트 | 확인한 것 |
|---|---|
| 부팅 | 배열 순서대로 초기화되고, 조이스틱의 소유자가 플레이어로 잡힌다 |
| 이동 | 끈 방향 그대로 조이스틱 값이 나오고 캐릭터가 움직인다 |
| 일시정지 | 플레이어와 조이스틱이 같이 멈추고, 재개하면 같이 돌아온다 |
| 딤 순서 | 팝업을 두 번 열어도 딤은 항상 팝업 뒤에 있다 |
| 일시정지 중 손 뗌 | 재개한 뒤 캐릭터가 저절로 움직이지 않는다 |

실행해 보면서 **결함 3건**을 더 찾아 고쳤습니다. 그중 2건은 위 정리 과정에서 생긴 것입니다.

| # | 증상 | 원인 |
|---|---|---|
| 1 | 끄는 중 일시정지 → 일시정지 중 손을 떼면 재개 후 캐릭터가 저절로 움직임 | 멈춘 동안 손 뗌 이벤트를 무시함 |
| 2 | 터치 영역을 화면 전체로 늘리면 조이스틱이 누른 자리가 아닌 곳에 생김 | 늘린 앵커에서 `sizeDelta` 는 0 |
| 3 | 팝업을 열면 딤이 팝업 앞으로 옴 | 같은 부모 안에서 순서를 옮길 때 번호가 하나 당겨짐 |
